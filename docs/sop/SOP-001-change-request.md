# SOP-001 – Raising and deciding a change request
**Owner:** PMO manager · **Applies to:** projects, products, programmes, services · **Review:** annually
1. Raise the CR (*Change control → New change request*) with type, justification, schedule and cost impact, risk level.
2. The platform creates the required impact assessments automatically (schedule, cost, scope, risk; BIA for critical contexts or IT/business change; security & operations for IT/infrastructure; vendor where contracts exist) and notifies assessor roles.
3. Assessors complete each assessment (rating + notes). When none are pending the CR moves to *pending approval*.
4. The owner submits the CR. It routes by cost to the change authority (approval matrix) with the finance controller in parallel where cost > 0.
5. Approvers decide (reason mandatory for rejection). On approval the project end date moves by the approved days and a forecast cost entry is recorded; both are audited.
6. Implement and record outcome; review in the next status report.
